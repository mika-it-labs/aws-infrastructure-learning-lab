# IAMの役割と確認観点

IAMの学習は実施済み（本人申告）です。以下は復習用の設計観点で、当時適用したポリシーの再現ではありません。

|主体|役割・確認する権限|
|---|---|
|学習者・構築実行者|対象サービスの設定操作。必要なロールに限定したiam:PassRole。渡す先のサービス条件も検討|
|CodePipelineサービスロール|ソースとアーティファクト用S3、CodeBuild開始・結果取得。Deployを追加する場合のみ必要なCodeDeploy操作|
|CodeBuildサービスロール|入力取得、成果物出力、CloudWatch Logs。アプリの実行ロールと混同しない|
|EC2インスタンスロール|SSM管理用権限、CodeDeploy Agentが使う対象S3配布物の読み取り等|
|CodeDeployサービスロール|デプロイグループに必要なAWSリソースの操作。EC2のS3読み取り権限とは別|
|KMSを使用する主体|暗号化方式とキーごとのDecrypt/GenerateDataKey等。キーポリシーも確認|

操作名だけでなく、主体、対象リソース、信頼ポリシー、バケットポリシー、KMS、明示的Denyを確認します。S3のバケット操作とオブジェクト操作では対象ARNが異なります。Resourceで制限できないAPIもあるため公式仕様に合わせます。

固定の万能ポリシーは収録しません。必要なリソースと機能を決めて最小権限を組み立てます。削除に必要な参照・関連付け解除権限も確認し、共有ロールやAWS管理ポリシーそのものを削除しません。
